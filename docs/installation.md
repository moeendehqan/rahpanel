# نصب و مدیریت Docker

## مسیر سریع

روی سرور پنل، Ubuntu 24.04 با معماری amd64 یا arm64، دسترسی root یا sudo و اینترنت برای دریافت imageها و وابستگی‌ها داشته باشید. دامنه پنل باید به IP همین سرور اشاره کند و TCP روی 80، 443 و 9443 قابل دسترسی باشد. برای نصب نود ترافیک روی همین ماشین، در فرم افزودن نود حالت «سرور مشترک» را انتخاب کنید؛ پورت‌های آن از پورت پنل جدا هستند.

نیازی به انتقال دستی سورس نیست. روی سرور:

```bash
curl -fsSL https://raw.githubusercontent.com/moeendehqan/rahpanel/main/bootstrap.sh | sudo bash -s -- --domain panel.example.com
sudo cat /opt/rahpanel/bootstrap-admin.txt
```

نام کاربری و گذرواژه را خصوصی بخوانید و به `https://panel.example.com` بروید. سپس تنظیمات Cloudflare را در پنل وارد کنید. نصب به ویرایش دستی فایل‌های سرویس، ساخت پایگاه داده یا نصب Go/Node نیاز ندارد.

اگر DNS پنل پشت پروکسی Cloudflare است، برای ارتباط مستقیم عامل‌ها یک hostname جدا با DNS-only بسازید:

```bash
curl -fsSL https://raw.githubusercontent.com/moeendehqan/rahpanel/main/bootstrap.sh | sudo bash -s -- --domain panel.example.com --agent-host agents.example.com
```

این hostname نیز به IP پنل اشاره می‌کند. endpoint آن `https://agents.example.com:9443` است. گواهی آن را CA داخلی پنل صادر می‌کند و عامل‌ها با همان CA اعتبارسنجی می‌کنند.

## رفتار نصب‌کننده

Bootstrap در پوشه `/opt/rahpanel` دریافت می‌شود. فرمان‌های `rah.sh` را پس از `cd /opt/rahpanel` اجرا کنید. اگر curl نصب نیست، ابتدا `sudo apt-get update && sudo apt-get install -y curl ca-certificates` اجرا کنید. `--dir` مسیر نصب و `--ref` شاخه یا tag نصب تازه را تعیین می‌کند. اجرای دوباره bootstrap فایل‌ها را reset یا pull نمی‌کند و پوشه نامرتبط یا مخزن متفاوت را رد می‌کند. تنظیمات Cloudflare و نصب نودها در پنل ادامه می‌یابند؛ ورود اول مستقیماً مرحله راه‌اندازی را نشان می‌دهد.

1. ورودی دامنه را بررسی می‌کند. دامنه متناقض با نصب قبلی را رد می‌کند.
2. اگر Docker وجود ندارد، روی Ubuntu/Debian و با root، مخزن رسمی apt و Docker Engine/Compose را نصب می‌کند. بسته‌های متداخل موجود خودکار حذف نمی‌شوند. مسیر نصب طبق [مستندات رسمی Docker](https://docs.docker.com/engine/install/ubuntu/) است.
3. image `rahpanel:local` را شامل رابط ساخته‌شده، API، ابزار مدیریت، عامل‌های amd64/arm64 و Xray بررسی‌شده می‌سازد.
4. تنها در نصب تازه، `.env` و `bootstrap-admin.txt` را با مجوز 0600 می‌سازد. کلید اصلی، رمز پایگاه داده، رمز مدیر تصادفی‌اند.
5. Compose را اعتبارسنجی و سرویس‌ها را با `--wait` اجرا می‌کند. پنل وقتی سالم است که پایگاه داده در دسترس باشد. Caddy پس از سلامت پنل اجرا می‌شود؛ ترتیب مبتنی بر سلامت طبق [مستندات Compose](https://docs.docker.com/compose/how-tos/startup-order/) است.

ساخت image پیش از ایجاد secrets انجام می‌شود؛ برای شکست دانلود، نصب دوباره قابل اجرا است. در اجراهای بعد، `.env` و volumeها حفظ می‌شوند. اجرای هم‌زمان نصب با قفل `.install.lock` جلوگیری می‌شود. اگر سیستم به‌طور ناگهانی خاموش شد، پیش از حذف این پوشه مطمئن شوید نصب دیگری در حال اجرا نیست.

روی میزبان با Docker آماده، از `--no-install-docker` استفاده کنید. نصب خودکار بسته‌ها به Ubuntu/Debian محدود است؛ روی دیگر سیستم‌ها Docker و Compose را جدا آماده کنید. اسکریپت نصب برای Bash روی لینوکس است.

## رفع خطا

| وضعیت | اقدام |
|---|---|
| Docker daemon در دسترس نیست | `sudo systemctl start docker` و اجرای مجدد با sudo؛ برای Docker rootless از کاربر مالک daemon استفاده کنید. |
| بسته Docker متداخل وجود دارد | مطابق راهنمای Docker بسته‌های قبلی را بررسی و مهاجرت کنید؛ نصب‌کننده آن‌ها را حذف نمی‌کند. |
| دانلود image یا Xray شکست خورد | دسترسی به Docker Hub، npm، proxy.golang.org و GitHub را بررسی و نصب را دوباره اجرا کنید. |
| مهلت سلامت سرویس تمام شد | `sudo bash rah.sh status` و `sudo bash rah.sh logs panel` یا `logs db`؛ پس از رفع علت نصب را دوباره اجرا کنید. |
| سایت HTTPS باز نمی‌شود ولی سرویس‌ها سالم‌اند | DNS، رکورد AAAA نادرست، TCP 80/443 و `sudo bash rah.sh logs edge` را بررسی کنید. بررسی سلامت Caddy فقط API محلی آن را می‌سنجد. |
| پورت قبلاً اشغال است | با `sudo ss -lntp` سرویس مالک 80/443/9443 را پیدا کنید. نصب‌کننده آن سرویس را متوقف نمی‌کند. |
| گذرواژه بعد از تغییر `.env` عوض نمی‌شود | مدیر اولیه فقط یک‌بار ساخته می‌شود؛ اجرای مجدد نصب رمز مدیر موجود را بازنشانی نمی‌کند. |

لاگ‌ها محدود به سه فایل ده‌مگابایتی برای هر سرویس هستند. پایگاه داده هیچ پورتی روی میزبان منتشر نمی‌کند؛ API مدیریت هم فقط از Caddy قابل دسترسی است. عامل‌ها روی 9443 با mTLS ارتباط دارند.

## پشتیبان و به‌روزرسانی

```bash
sudo bash rah.sh backup
# سورس نسخه مشخص را دریافت کنید، سپس:
sudo bash rah.sh update
```

`update` پیش از ساخت از DB پشتیبان می‌گیرد و در صورت شکست پشتیبان‌گیری ادامه نمی‌دهد. پشتیبان DB برای بازیابی به `.env` و `MASTER_KEY` همان نصب نیاز دارد. `.env`، فایل اطلاعات مدیر و داده‌های Caddy را جدا و امن نگه دارید. تغییر image به نسخه قبلی، تغییرات schema را برنمی‌گرداند؛ برای بازیابی از پشتیبان و سورس سازگار استفاده کنید. بازیابی ابتدا ساختار آرشیو را بررسی می‌کند، تأیید تایپی می‌گیرد و از وضعیت فعلی پشتیبان می‌سازد. جایگزینی DB در یک تراکنش انجام می‌شود تا شکست میانی تغییرات را برگرداند؛ پنل پس از موفقیت یا شکست دوباره شروع می‌شود.

## وضعیت اعتبارسنجی

آزمون محلی نصب با Docker شبیه‌سازی‌شده، نصب تازه، حفظ secrets، شکست و تلاش مجدد، رد دامنه نامعتبر و چاپ‌نشدن اطلاعات ورود را بررسی می‌کند. آزمون Go پاسخ سلامت موفق، ناموفق و قطع ارتباط را پوشش می‌دهد. [اجرای موفق CI](https://github.com/moeendehqan/rahpanel/actions/runs/42213101056) ساخت image واقعی، اجرای سالم هر سه سرویس و ماندگاری DB پس از بازسازی کانتینرها را تأیید کرد. آزمون‌های Go با race detector و آزمون‌های نصب نیز موفق بودند. دانلود عمومی bootstrap و clone واقعی مخزن بررسی شدند. نصب با DNS عمومی و مسیر apt روی Ubuntu تازه همچنان به آزمون میدانی نیاز دارد.
