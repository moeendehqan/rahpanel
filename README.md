# راه — Rah Panel

پنل مستقل مدیریت کاربران و چند سرور Xray؛ ساخته‌شده از صفر با Go، PostgreSQL و React/TypeScript. رابط فارسی است و کاربران از کلاینت‌های آماده استفاده می‌کنند.

## چه چیزی پیاده‌سازی شده است؟

- مدیریت کاربران، گروه نودها، انقضا، سهمیه، تعلیق و اشتراک قابل ابطال.
- ورود مدیر با bcrypt و نشست HttpOnly/SameSite.
- ثبت نود و نصب worker با SSH و تأیید اثر انگشت میزبان؛ رمز/کلید SSH در DB یا صف پایدار ذخیره نمی‌شود.
- Cloudflare DNS-only، دریافت و تمدید گواهی DNS-01 در پنل، هویت mTLS مستقل برای نود.
- سه قالب VLESS/REALITY، VLESS/WS/TLS و Trojan/TLS با پورت‌های قابل انتخاب برای هر نود.
- آزمون احراز هویت از پنل با Xray و درخواست HTTPS از داخل تونل، پیش از انتشار هر روش.
- عامل systemd، گزارش مصرف هر ۳۰ ثانیه، outbox پایدار و حذف شمارش تکراری در PostgreSQL.
- انقضای محلی و watchdog مستقل با مهلت uptime حداکثر ۲۹۵ ثانیه، با حاشیه توقف برای سقف پنج دقیقه.
- لاگ عملیات مدیر؛ بدون تاریخچه مقصد و محتوای ترافیک.

## نصب با یک فرمان

روی Ubuntu 24.04 اجرا کنید؛ کد از GitHub دریافت و در `/opt/rahpanel` نصب می‌شود:

```bash
curl -fsSL https://raw.githubusercontent.com/moeendehqan/rahpanel/main/bootstrap.sh | sudo bash -s -- --domain panel.example.com
```

`panel.example.com` را با دامنه خودتان عوض کنید و DNS آن را به IP سرور وصل کنید. اگر `--domain` را حذف کنید، دامنه از طریق ترمینال پرسیده می‌شود. اگر curl نصب نیست، یک‌بار `sudo apt-get update && sudo apt-get install -y curl ca-certificates` اجرا کنید. اطلاعات ورود:

```bash
sudo cat /opt/rahpanel/bootstrap-admin.txt
```

پس از ورود، پنل خودکار مرحله تنظیم Cloudflare را باز می‌کند. آدرس‌های پنل و عامل از نصب پر شده‌اند؛ بعد از ذخیره، افزودن نود، SSH، نصب و ساخت کاربران را در پنل ادامه دهید.

برای دریافت نسخه مشخص از `--ref TAG` استفاده کنید. روی نصب موجود، اجرای دوباره bootstrap سورس و secrets را بازنشانی نمی‌کند. مخزن: [moeendehqan/rahpanel](https://github.com/moeendehqan/rahpanel).

اگر سورس را قبلاً دریافت کرده‌اید، داخل پوشه آن هم می‌توانید اجرا کنید:

```bash
sudo bash install.sh --domain panel.example.com
```

دامنه را با دامنه خودتان عوض کنید. نصب‌کننده، Docker و Compose را در صورت نبودن روی Ubuntu/Debian از مخزن رسمی نصب می‌کند، image را می‌سازد، کلیدها و رمزهای تصادفی تولید می‌کند و PostgreSQL، پنل و Caddy را تا سالم‌شدن بالا می‌آورد. به نصب Go، Node یا PostgreSQL روی میزبان نیازی نیست. دریافت اولیه وابستگی‌ها و Xray به اینترنت نیاز دارد.

قبل از نصب، DNS دامنه را به IP سرور وصل و پورت‌های TCP 80، 443 و 9443 را باز کنید. Caddy گواهی HTTPS عمومی را خودکار می‌گیرد. بررسی سلامت سرویس‌ها جای آزمون دسترسی عمومی دامنه و گواهی را نمی‌گیرد. endpoint عامل روی 9443 باید DNS-only و مستقیم باشد؛ برای hostname جدا از `--agent-host agents.example.com` استفاده کنید. برای نود روی همین ماشین، حالت «سرور مشترک» را انتخاب کنید تا پورت اتصال نود با HTTPS پنل تداخل نداشته باشد.

نام کاربری و رمز عبور در `bootstrap-admin.txt` ذخیره می‌شوند؛ با `sudo cat bootstrap-admin.txt` آن را خصوصی بخوانید. رمزها در خروجی نصب چاپ نمی‌شوند. فایل را امن و آفلاین نگه دارید. شناسه مدیر فقط در اولین راه‌اندازی DB ساخته می‌شود. کلید `MASTER_KEY` در `.env` را همراه پشتیبان و جدا از آن نگهداری کنید؛ تعویض یا گم‌کردن آن داده‌های رمزگذاری‌شده را غیرقابل‌بازیابی می‌کند.

اجرای دوباره `sudo bash install.sh` تنظیمات و volumeهای قبلی را نگه می‌دارد. اگر Docker و Compose از قبل آماده‌اند، `bash install.sh --domain panel.example.com --no-install-docker` هم کار می‌کند. نصب‌کننده نرم‌افزار کانتینر موجود را خودکار حذف نمی‌کند. [جزئیات نصب و رفع خطا](docs/installation.md).

## فرمان‌های مدیریت

ابتدا `cd /opt/rahpanel` را اجرا کنید (یا به مسیر نصب انتخابی خود بروید).

```bash
sudo bash rah.sh status          # وضعیت و سلامت
sudo bash rah.sh logs            # مشاهده لاگ‌ها (Ctrl+C برای خروج)
sudo bash rah.sh restart         # راه‌اندازی مجدد
sudo bash rah.sh stop            # توقف با حفظ داده‌ها
sudo bash rah.sh start           # شروع دوباره
sudo bash rah.sh backup          # پشتیبان پایگاه داده
sudo bash rah.sh restore backups/rah-DATE.dump
sudo bash rah.sh update          # پشتیبان، ساخت سورس فعلی و راه‌اندازی
```

برای به‌روزرسانی، ابتدا سورس نسخه موردنظر را دریافت کنید؛ فرمان `update` خودکار شاخه یا نسخه‌ای از اینترنت انتخاب نمی‌کند. پایگاه داده و داده‌های Caddy در volumeهای پایدار هستند. `docker compose down --volumes` داده‌ها را حذف می‌کند؛ برای توقف از `rah.sh stop` استفاده کنید.

برای انتشار خودکار از `main`، در GitHub از بخش **Settings → Secrets and variables → Actions** این secrets را اضافه کنید:

- `DEPLOY_HOST` و `DEPLOY_USER` برای اتصال SSH به سرور پنل.
- `DEPLOY_SSH_KEY` کلید خصوصی اختصاصی و بدون passphrase برای اجرای غیرتعاملی. کلید عمومی متناظر را در `authorized_keys` کاربر انتشار قرار دهید.
- `DEPLOY_KNOWN_HOSTS` رکورد کلید میزبان SSH که از مسیر مطمئن تأیید کرده‌اید.

سرور باید از GitHub Actions قابل دسترسی باشد. کاربر SSH باید به Git و Docker در نصب موجود در `/opt/rahpanel` دسترسی داشته باشد. بعد از هر push به `main`، در صورت موفقیت تست‌ها و بررسی Docker، workflow روی سرور از دیتابیس پشتیبان می‌گیرد، نسخه را می‌سازد و سلامت پنل را بررسی می‌کند.

ساخت image نسخه مشخص Xray را از release رسمی می‌گیرد و checksum رسمی را بررسی می‌کند. نسخه پیش‌فرض آزمون‌شده قالب‌ها `v25.3.6` است؛ تغییر نسخه باید همراه آزمون سازگاری و ساخت release تازه باشد. آخرین نسخه به‌صورت خودکار روی نودها نصب نمی‌شود.

پس از ورود، در «تنظیمات» وارد کنید:

1. دامنه پایه نودها و Cloudflare Zone ID.
2. توکن محدود به همان Zone، با DNS Edit و Zone Read.
3. ایمیل ACME؛ آدرس‌های پنل و عامل خودکار از نصب خوانده می‌شوند.
4. مقصد TLS مناسب REALITY و SNI متناظر؛ مقدار پیش‌فرض صرفاً نقطه شروع آزمون است.

Let’s Encrypt برای هر نود گواهی جدا صادر می‌کند و محدودیت نرخ دارد؛ برای تمرین از staging directory استفاده کنید. گواهی staging در آزمون TLS عمومی معتبر نیست و اتصال‌ها تا استفاده از گواهی معتبر منتشر نمی‌شوند.

## افزودن نود

Ubuntu 24.04، amd64 یا arm64، حداقل ۵۱۲ مگابایت فضای آزاد، IP قابل‌دسترسی و SSH با root یا sudo بدون تعامل لازم است. نصب‌کننده مالکیت پورت‌ها را بررسی می‌کند، ولی فایروال یا Security Group ارائه‌دهنده را نمی‌تواند بدون API آن تغییر دهد. پورت‌های TCP انتخاب‌شده برای REALITY، WebSocket و Trojan را باز کنید و خروجی HTTPS به پنل و اینترنت را مجاز کنید.

برای استفاده از سرور پنل، در «افزودن سرور» IP همان سرور و گزینه «این نود روی سرور پنل یا کنار سرویس‌های دیگر نصب می‌شود» را انتخاب کنید. پیش‌فرض این حالت REALITY=2087، WebSocket=8443، Trojan=2053 و آمار داخلی=10086 است. پورت‌های 80/443/9443 برای پنل محفوظ‌اند. بخش اختیاری پورت‌ها در فرم معرفی و نصب قابل تنظیم است؛ پس از خطای تداخل در پیش‌بررسی می‌توان پورت تازه انتخاب کرد. پس از فعال‌سازی هویت نود، حتی اگر تأیید اتصال ناموفق بوده باشد، پورت‌ها در نصب مجدد ثابت می‌مانند تا تنظیم هسته و عامل از هم جدا نشوند.

در اولین نصب نود مستقل، اگر Nginx استاندارد Ubuntu پورت TCP 443 را گرفته باشد، پنل می‌تواند همان پورت را بر اساس SNI بین REALITY و سایت‌ها تقسیم کند. لینک اشتراک روی 443 می‌ماند و پورت‌های محلی 2087 و 8444 باید آزاد باشند. SNI نود باید از نام سایت‌ها جدا باشد. نصب‌کننده از فایل‌های تغییرکرده در `/etc/rahpanel/nginx-before-reality` نسخهٔ پشتیبان می‌گیرد و در صورت شکست بررسی یا بارگذاری کانفیگ، آن‌ها را برمی‌گرداند. سایت‌هایی که از این مسیر سرو می‌شوند، آدرس اتصال محلی Nginx را می‌بینند. چیدمان‌های پشتیبانی‌نشده یا سایر تداخل‌های پورت در پیش‌بررسی خطا می‌دهند.

API آمار فقط روی loopback است و نباید در فایروال عمومی باز شود. در نصب مجدد، وجود فایل managed به‌تنهایی مجوز نادیده‌گرفتن تداخل نیست؛ پورت‌های Xray باید آزاد یا در اختیار همان `rah-xray.service` باشند.

در «سرورها»، نام، IP و گروه را ثبت کنید؛ اثر انگشت SSH را با کنسول ارائه‌دهنده مقایسه و سپس دسترسی نصب را وارد کنید. مراحل در «عملیات نصب» نمایش داده می‌شوند. شکست نصب قابل تکرار است؛ پس از restart پنل، نصب‌های نیمه‌تمام interrupted می‌شوند و باید اعتبارنامه SSH دوباره وارد شود. نصب مجدد همان نود هویت قبلی را باطل می‌کند و ممکن است اتصال‌های باز را قطع کند.

کلاینت مرجع موردنظر v2rayNG و v2rayN است. لینک اشتراک را اضافه کنید و برای پوشش کل دستگاه TUN/VPN را در کلاینت فعال کنید. تنظیم System Proxy کافی نیست. تعویض خودکار وابسته به کلاینت است و این نسخه وعده قابلیت یکسان در همه کلاینت‌ها نمی‌دهد.

## پشتیبان و نگهداری

```bash
bash scripts/backup.sh
bash scripts/restore.sh backups/rah-DATE.dump
```

بازیابی DB به همان `MASTER_KEY` نیاز دارد؛ CA نودها و کلید ACME داخل DB رمزگذاری می‌شوند. اسکریپت restore تأیید صریح می‌خواهد چون DB فعلی را جایگزین می‌کند. فایل‌های `.env`، گواهی Caddy و تنظیم دامنه را هم جداگانه پشتیبان بگیرید.

گواهی وب نودها در پنل پیش از پایان اعتبار تمدید می‌شود. هویت mTLS نود و endpoint نیز پیش از انقضا خودکار تمدید می‌شود؛ هویت قبلی نود برای بازیابی پاسخ گم‌شده، ۲۴ ساعت مهلت دارد. نودی که تا پس از انقضای گواهی آفلاین بماند، به نصب مجدد نیاز دارد. CA و کلید اصلی پنل را همراه پایگاه داده پشتیبان بگیرید.

در خطای حسابداری عامل متوقف و در quarantine باقی می‌ماند؛ عمداً با restart به انتقال بدون شمارش برنمی‌گردد. پس از بررسی `journalctl -u rah-agent`، سلامت دیسک و state، نیاز به بازیابی دستی مصرف و رفع marker `/etc/rahpanel/accounting-blocked` و فیلد `accounting_blocked` در state است. این اقدام را بدون تطبیق مصرف انجام ندهید.

## توسعه و بررسی

```bash
go test ./...
go vet ./...
cd web
npm ci --legacy-peer-deps
npm test
npm run build
```

برای تست DB، `TEST_DATABASE_URL` باید به PostgreSQL آزمایشی و قابل‌حذف اشاره کند؛ تست‌ها جداول خود را پاک می‌کنند. تست API از schema جدا استفاده می‌کند.

```bash
TEST_DATABASE_URL='postgres://rah:test@localhost:5432/rah_test?sslmode=disable' go test ./...
RUN_CAPACITY_TEST=1 TEST_DATABASE_URL='postgres://rah:test@localhost:5432/rah_test?sslmode=disable' go test ./internal/store -run TestControlPlaneCapacity -v
```

پنل برای توسعه متغیرهای `DATABASE_URL`، `MASTER_KEY`، `ADMIN_USERNAME`، `ADMIN_PASSWORD`، `PUBLIC_URL` و `AGENT_URL` را از محیط می‌گیرد. برای HTTP صرفاً محلی `INSECURE_DEV=true` لازم است. فایل `.env` در اجرای مستقیم Go خودکار بارگذاری نمی‌شود؛ Compose آن را می‌خواند. در dev با Vite، `PUBLIC_URL` را برابر origin آن قرار دهید تا بررسی Origin معتبر بماند.

این پروژه هنوز به آزمون نصب روی دو Ubuntu واقعی، Cloudflare/ACME واقعی، کلاینت‌های مرجع، بازیابی عملی و شبکه ایران نیاز دارد. تست‌های محلی جای آن‌ها را نمی‌گیرند؛ وضعیت دقیق در [acceptance.md](docs/acceptance.md) ثبت می‌شود. هیچ تضمین غیرقابل‌شناسایی بودن یا اتصال هنگام قطع کامل مسیرهای خارجی ارائه نمی‌شود.
